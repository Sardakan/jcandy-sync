## Цель

Микросервис синхронизирует каталог, заказы и контрагентов между сайтом и МойСклад. Изменения, полученные от сайта, передаются в МойСклад через надёжную очередь. Изменения, инициированные в МойСклад, передаются на сайт вебхуками.

## Карта потоков

| Направление | Сущность | Результат |
| --- | --- | --- |
| Сайт -> МойСклад | Товар | Создание или полная перезапись карточки товара. |
| Сайт -> МойСклад | Заказ | Создание заказа либо обновление его статуса. |
| Сайт -> МойСклад | Возврат | Создание или обновление возврата покупателя либо уменьшение неотгруженного заказа. |
| Сайт -> МойСклад | Контрагент | Создание или обновление карточки покупателя. |
| МойСклад -> сайт | Товар | Передача полной карточки товара. |
| МойСклад -> сайт | Заказ | Передача статуса заказа. |
| МойСклад -> сайт | Контрагент | Передача изменений карточки покупателя. |

## Синхронизация товаров

### Цель

Перенести карточку товара с сайта в МойСклад и поддерживать её актуальной.

### Правила

1. Товар ищется по штрихкоду (`barcode`).
2. Если товар уже существует, его карточка полностью перезаписывается. Если нет - создаётся новая.
3. Передаются наименование, описание, штрихкод, артикул, обычная и старая цены, страна, бренд, признак публикации, магазин и код ТН ВЭД ЕАЭС.
4. Страна и значение справочника «Магазин» создаются в МойСклад, если их ещё нет.
5. Из нескольких изображений передаётся первое. SVG пропускается, потому что МойСклад его не поддерживает.
6. При обработке заказа товар, отсутствующий в МойСклад, дополнительно может быть создан из карточки сайта.

### Массовая миграция

Массовая миграция получает товары с сайта порциями по 50. Каждая порция разбивается на подгруппы по 25 товаров для отправки в МойСклад. Между подгруппами выдерживается пауза 15 секунд. Товары, которые не удалось обработать, помещаются в очередь для повторной попытки.

## Синхронизация заказов

### Цель

Создать заказ сайта в МойСклад и поддерживать его состояние.

### Правила

1. Заказ связан с сайтом через `externalCode`, равный `orderId` или `id` заказа.
2. Перед созданием заказа сервис создаёт или обновляет его контрагента по email.
3. В заказ добавляются найденные в МойСклад товары. Если товар отсутствует, сервис запрашивает его с сайта и пытается создать автоматически.
4. Платная доставка добавляется как услуга. Наименование берётся из `deliveryTariffName`, а при его отсутствии используется «Доставка».
5. Для нового заказа передаются дата, адрес доставки, комментарий, организация, склад, канал продаж, позиции и непустой статус.
6. Если заказ уже существует, сервис обновляет только его статус. Состав позиций, адрес, комментарий и другие поля обычного заказа не перезаписываются.
7. При создании заказа со статусом `cancelled` резерв позиций устанавливается в ноль. Для уже созданного заказа изменение статуса не меняет резерв автоматически.
8. Для доставки СДЭК сервис запрашивает с сайта этикетку и прикрепляет её к заказу как файл. Недоступность этикетки не отменяет создание заказа.

### Ограничения

- Поддерживаются только статусы, заданные в настройках: `pending`, `processing`, `shipped`, `delivered`, `cancelled`.
- Пустой или отсутствующий статус не передаётся в МойСклад. Для нового заказа МойСклад применяет состояние по умолчанию, для существующего сохраняется текущее.

## Возвраты покупателя

### Цель

Обработать полный или частичный возврат товара, переданный сайтом для существующего заказа.

### Правила

1. Возврат обрабатывается только для существующего заказа МойСклад.
2. Отменяемые товары передаются отдельным списком `returnedItems`; одинаковые штрихкоды суммируются.
3. Если у заказа есть отгрузка, сервис использует первую отгрузку и создаёт или полностью перезаписывает один связанный документ «Возврат покупателя».
4. Для возврата используются цена и НДС из позиции первой отгрузки.
5. Если отгрузки нет, количества вычитаются из позиций исходного заказа. Позиция с нулевым количеством удаляется.
6. Количество возврата не может быть нулевым, отрицательным или больше количества в отгрузке либо текущем заказе.
7. Непустой статус обновляет состояние заказа; пустой или отсутствующий статус сохраняет текущее состояние МойСклад.

### Повторные запросы

Для заказа создаётся один документ возврата с тем же `externalCode`. Каждый новый запрос полностью перезаписывает его актуальными позициями: ранее возвращённые количества не суммируются.

### Ограничения и проверки

- Обрабатывается только первая отгрузка заказа.
- Связь возврата с отгрузкой требует подтверждения реальным запросом в тестовый МойСклад.
- Услуга доставки без штрихкода остаётся в неотгруженном заказе и не включается в возврат.

Подробный входной контракт, алгоритм и чек-лист проверок приведены в `PARTIAL_CANCELLATION_PLAN.md`.

## Синхронизация контрагентов

### Цель

Создать или обновить покупателя на основании данных сайта.

### Правила

1. Контрагент ищется по email.
2. Если контрагент найден, его карточка обновляется; иначе создаётся новая.
3. Передаются имя, email, телефон, адрес и идентификаторы сайта.
4. Адрес-объект преобразуется в строку из индекса, города и улицы.
5. Пустые телефон и адрес не передаются, поэтому не затирают существующие данные МойСклад.

## Вебхуки МойСклад -> сайт

### Товары

При изменении товара в МойСклад сервис получает полную карточку и передаёт на сайт наименование, штрихкод, описание, бренд, признак публикации, страну, текущую и старую цены, а также ТН ВЭД ЕАЭС.

### Контрагенты

При изменении контрагента сервис передаёт на сайт email, имя, телефон, адрес, внешний идентификатор и заметки. Контрагент без email пропускается.

### Заказы

При изменении заказа сервис определяет статус по настройкам и передаёт его на сайт по `externalCode`. Неизвестное состояние МойСклад передаётся как `pending`. Заказ без `externalCode` пропускается.

### Остатки

Синхронизация остатков из документов МойСклад в настоящее время отключена по требованию заказчика. Изменения документов не обновляют остатки товаров на сайте.

## Очередь и ошибки

### Правила

1. Все входящие запросы сайта на создание или изменение ставятся в очередь и сразу получают подтверждение постановки.
2. Задачи выполняются последовательно с задержкой 3 секунды между обработками.
3. При ошибке задача повторяется до трёх раз.
4. После третьей неудачи задача переносится в `failed_queue.json` для ручного разбора и не блокирует остальные задачи.
5. Задачи и неудачные задачи сохраняются на диске, поэтому очередь восстанавливается после перезапуска сервиса.

## Миграции и обслуживание

### Разовые миграции

Сервис поддерживает запуск миграции заранее заданного тестового списка товаров, заказов и контрагентов. Этот механизм не предназначен для произвольного выбора идентификаторов в запросе.

### Доступность во время массовой миграции

Во время массовой миграции сервис периодически обращается к своему `/ping`, чтобы Render не перевёл приложение в спящий режим. Самопрозвон прекращается после завершения миграции и очереди ошибок.

### Логи

Все операции записываются в `sync.log` и выводятся в стандартный поток. При запуске и затем раз в сутки сервис удаляет записи старше заданного срока. Если размер лога превышает установленный лимит, сохраняются самые свежие записи. По умолчанию срок хранения - 7 дней, лимит - 100 МБ.
