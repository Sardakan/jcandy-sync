# План: возвраты покупателя из сайта в МойСклад

## Цель

При возврате товаров сайт передаёт обновление существующего заказа в микросервис. Сервис создаёт или обновляет связанный документ «Возврат покупателя» (`salesreturn`) в МойСклад, не изменяя состав исходного заказа.

## Входной контракт

Используется существующий маршрут:

```text
PATCH /api/v1/external/orders/:id
```

Пример запроса:

```json
{
  "id": "ORDER-123",
  "status": "cancelled",
  "return": true,
  "items": [
    {
      "barcode": "4601234567890",
      "quantity": 1
    }
  ]
}
```

- `return: true` запускает обработку возврата.
- `items` содержит фактически возвращаемые позиции и их количество.
- Для полного возврата сайт передаёт в `items` все товары заказа.
- Для частичного возврата сайт передаёт только возвращаемые товары.

## Алгоритм

1. Найти заказ МойСклад по `externalCode`, равному `orderId` или `id` сайта.
2. Убедиться, что заказ содержит хотя бы одну отгрузку в `demands`.
3. Использовать метаданные первой отгрузки `demands[0].meta` как связь `demand` нового документа возврата.
4. Загрузить позиции первой отгрузки.
5. Для каждой позиции `items` найти товар МойСклад по штрихкоду и проверить, что он присутствует в отгрузке, а количество возврата не больше отгруженного.
6. Сформировать позиции `salesreturn`, используя ассортимент товара, количество, цену и НДС исходной отгрузки.
7. Найти существующий `salesreturn` по `externalCode` заказа:
   - если его нет, создать новый документ;
   - если состав совпадает с полученным от сайта, ничего не менять;
   - если состав отличается, обновить существующий документ.
8. Обновить статус заказа МойСклад по значению `status` из сайта.

## Идемпотентность

`externalCode` возврата равен `externalCode` заказа. Поэтому для одного заказа поддерживается один синхронизируемый возврат: повторный запрос с тем же составом не создаёт второй документ, а изменившийся состав приводит документ к актуальному состоянию сайта.

## Ограничения

- Обрабатывается только первая отгрузка: `demands[0]`.
- Возврат без отгрузки не создаётся и повторяется очередью.
- Услуги доставки без штрихкода не входят в текущий контракт возврата.
- Товар, не найденный в МойСклад, нулевое/отрицательное количество или количество выше отгруженного считаются ошибкой задачи.

## Проверки перед пушем

1. `npm test` — unit-тесты Mocha + Chai.
2. Ручные прогоны в тестовом МойСклад: частичный возврат, полный возврат, повтор идентичного запроса и изменение состава существующего возврата.
