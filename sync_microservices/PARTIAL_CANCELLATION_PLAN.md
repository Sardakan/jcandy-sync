## Цель

При возврате товаров сайт передаёт обновление существующего заказа в микросервис. Для отгруженного заказа сервис создаёт или обновляет связанный документ «Возврат покупателя» (`salesreturn`); для неотгруженного — уменьшает количества исходного заказа в МойСклад.

## Входной контракт

Используется существующий маршрут:

```text
PATCH /api/v1/external/orders/:id
```

Пример запроса:

```json
{
  "id": "ORDER-123",
  "status": "cancelled",
  "return": true,
  "returnedItems": [
    {
      "barcode": "4601234567890",
      "quantity": 1
    }
  ]
}
```

- `return: true` запускает обработку возврата.
- `returnedItems` содержит отменяемые позиции и количество для вычитания.
- Для полного возврата сайт передаёт в `returnedItems` все товары заказа.
- Для частичного возврата сайт передаёт только отменяемые товары.

## Алгоритм

1. Найти заказ МойСклад по `externalCode`, равному `orderId` или `id` сайта.
2. Проверить непустой массив `returnedItems`, штрихкоды и положительные количества; одинаковые штрихкоды суммируются.
3. Если есть хотя бы одна отгрузка в `demands`, использовать метаданные первой отгрузки `demands[0].meta` как связь `demand` документа возврата.
4. Загрузить позиции первой отгрузки, проверить наличие товара и достаточность количества, затем сформировать позиции `salesreturn` с ценой и НДС отгрузки.
5. Найти `salesreturn` по `externalCode` заказа: создать документ, если его нет, либо полностью перезаписать текущими `returnedItems`.
6. Если отгрузки нет, загрузить позиции `customerorder`, вычесть количества из `returnedItems`, удалить позиции с нулевым остатком и перезаписать заказ в МойСклад.
7. Передать состояние заказа только при непустом `status`; иначе сохранить текущее состояние МойСклад.

## Повторные запросы

`externalCode` возврата равен `externalCode` заказа, поэтому для одного заказа поддерживается один документ `salesreturn`. Каждый входящий запрос полностью перезаписывает его текущими данными `returnedItems`: одинаковые запросы не пропускаются, количества прежнего возврата не накапливаются.

## Ограничения и риски

- Обрабатывается только первая отгрузка: `demands[0]`.
- Поле связи `demand: { meta: demandMeta }` требует подтверждения реальным запросом в тестовый МойСклад.
- Услуги доставки без штрихкода сохраняются в неотгруженном заказе и не могут быть включены в `returnedItems`.
- Товар, не найденный в МойСклад, нулевое/отрицательное количество, отсутствие товара в документе или количество выше доступного считаются ошибкой задачи.
